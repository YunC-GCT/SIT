# 02 — 地图处理与起终点交互

**What to build:** 用户能够选择地图并只通过一次起点、一次终点交互完成建图输入；系统生成包含栅格地图、物理尺度、坐标系和起终点的 JSON 产物，并支持无显示器参数输入。

**Blocked by:** 01 — 运行批次与统一 JSON 契约基础

**Status:** resolved

- [x] 图形模式只接受起点和终点两个点击，显示栅格位置和空闲/障碍状态
- [x] 支持 Enter 确认、R 重置、右键撤销和 Esc 取消
- [x] 起终点落在障碍格时要求重新选择，不静默移动
- [x] 普通模式默认使用配置栅格宽度，主动调整时才进入设置
- [x] 无显示器模式通过显式参数提供像素或栅格起终点，并保存预览结果
- [x] 输出版本化 JSON，供规划器独立读取
- [x] 为坐标映射、障碍点校验、交互取消和无显示器参数建立测试

## Answer

已完成地图处理与起终点交互重构：

- GUI 只接受起点、终点两个点击，支持 Enter 确认、R 重置、右键撤销和 Esc/关闭窗口取消，并显示 row/col 及空闲/障碍状态。
- 起终点落在障碍格时直接失败并要求重新选择，不再自动移动。
- 普通交互入口默认使用配置栅格宽度，只有 `--adjust-grid` 才进入调参。
- `map_pipeline.json_pipeline` 支持显式栅格或像素坐标的无显示器 CLI，生成带版本、坐标系、物理尺度、起终点和预览路径的 JSON。
- CLI 默认创建独立 `RunBatch`，失败和取消均写入结构化错误及 manifest；新增坐标、栅格参数、预览和无显示器测试。

验证：`python -m unittest discover -v` 通过 17 个测试。
