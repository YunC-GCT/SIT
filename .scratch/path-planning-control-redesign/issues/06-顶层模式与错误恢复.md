# 06 — 顶层普通模式、研究模式与错误恢复

**What to build:** 顶层系统能够串联各独立模块，提供普通模式和研究模式，减少重复交互；模块失败时暂停当前运行批次并提供定位、重试和返回操作，不让普通错误直接终止整个系统。

**Blocked by:** 02、03、04、05

**Status:** resolved

- [x] 普通模式使用默认算法、栅格宽度和 turn 模式，只保留起终点、路径预览和驱动前确认
- [x] 研究模式支持多算法、参数、随机种子、指标和结果对比，默认不驱动车
- [x] 路径预览同时承担路径接受确认，显示开环提示和预计执行信息
- [x] 支持无显示器运行和显式起终点参数
- [x] 模块错误显示模块、阶段、输入、原因和建议动作，并写入运行批次
- [x] 交互模式支持重试、修改参数、返回上一步和退出；批处理模式返回非零状态
- [x] 任务完成后支持相同批次重跑、更换算法、重新后处理、重新选点、切换地图和退出
- [x] 顶层集成测试覆盖成功、失败、重试、headless 和不启动后续运动

## Answer

新增 `core.orchestrator` 作为顶层深模块，`main.py` 提供普通/研究模式 CLI。模块 CLI 通过同一 `run_id` 串联，manifest 支持版本化重试尝试、结构化错误、路径预览和运动跳过状态。研究模式不会启动运动；headless 模式要求显式起终点，只有同时提供 `--drive --accept-path --yes` 才允许进入运动控制。

测试覆盖 42 项，包括真实模块 CLI 串联、成功、失败、重试、研究模式、headless 预览和运动控制未启动。
