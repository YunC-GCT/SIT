# TurboPi 路径规划与循迹系统重构规格

Status: ready-for-agent

## Problem Statement

当前项目能够把地图图片、栅格地图、路径规划和 TurboPi 底盘控制串联起来，但各阶段仍依赖旧的 YAML、TXT、NPY/NPZ 文件和固定目录。交互流程包含重复确认，运动控制假设存在 `/odom`，而实际底盘只有 `/cmd_vel` 和 IMU；多个商家功能节点还可能同时发布速度命令。路径规划算法的原始结果也没有经过统一的平滑、碰撞复核和可执行分段。

用户希望以路径规划算法的研究和改良为核心，同时让小车能够按照规划路径完成基本跟随。程序需要在树莓派 Debian 12 宿主机的 `aarch64` 环境中，通过 `turbopi:new` Docker 容器内的 Ubuntu 22.04、ROS2 Humble 和 Python 3.10 运行，并参考商家 `Twist` 示例的运动语义。

## Solution

重构为可扩展的模块化流水线。地图处理、路径规划、路径后处理和运动控制作为当前能力分组，但不构成永久固定的模块清单；未来可以增加定位、感知、避障或里程计模块。模块通过带版本、状态、元数据和错误信息的 JSON 契约单向连接，各模块同时提供独立 Python API 和 CLI。

规划器输出候选原始路径，路径后处理器使用自研的分段三次样条进行基础平滑，随后离散采样、碰撞复核和最大段长分解，最终输出控制器使用的路径段。第一版不追求样条参数最优，但保留可替换的平滑器边界，后续可接入成熟库。

运动控制器默认采用 `turn` 模式：根据路径段方向计算转角，先使用 `angular.z` 原地转向，发布短暂零速度，再使用 `linear.x` 沿车头方向前进。初始车头为地图正北，地图上方为北、下方为南、左方为西、右方为东。底盘命令发布到绝对话题 `/cmd_vel`，没有 `/odom` 时以实测经验速度约 `0.30 m/s` 进行 timer 开环估算，并明确标记该模式的非精确性。

普通模式保留最少必要交互；研究模式开放多算法、参数和指标比较。模块错误暂停当前运行批次并给出可操作反馈，运动控制异常或任何退出路径都必须先安全停车，再结束 ROS2。

## User Stories

1. 作为项目研究者，我希望只替换一个路径规划算法而不修改建图、路径后处理或运动控制，以便公平比较算法。
2. 作为项目研究者，我希望增加新的能力模块而不改动所有旧模块，以便后续加入定位、避障或里程计研究。
3. 作为项目研究者，我希望每次实验使用独立的运行批次，以便不同地图、算法参数和结果不会相互覆盖。
4. 作为项目研究者，我希望所有模块输出带版本和状态的 JSON，以便人工检查、跨语言读取和长期保存实验结果。
5. 作为地图使用者，我希望在地图窗口中只点击一次起点和一次终点，以便快速完成必要输入。
6. 作为地图使用者，我希望看到起点、终点、所在栅格以及是否落在障碍物上的即时反馈，以便及时修正错误选点。
7. 作为地图使用者，我希望使用 R 重置起终点、Enter 确认、Esc 取消，以便不必重新启动整个程序。
8. 作为地图使用者，我希望普通运行直接使用默认栅格宽度，只有主动调整时才进入栅格设置，以便减少不必要的终端交互。
9. 作为普通演示用户，我希望程序默认使用配置中的算法和 `turn` 运动模式，以便不必每次输入算法编号和运动模式。
10. 作为算法研究者，我希望一次选择多个规划算法并获得统一指标，以便比较路径质量和规划性能。
11. 作为算法研究者，我希望随机规划算法记录随机种子，以便重复实验并解释结果差异。
12. 作为路径研究者，我希望原始路径先经过平滑、碰撞复核和分段，以便控制器执行的是可验证路径而不是算法内部节点。
13. 作为路径研究者，我希望平滑失败时回退到已验证的原始路径，以便基础系统仍能运行并记录平滑问题。
14. 作为控制开发者，我希望运动控制器只读取统一路径段，不关心路径来自哪一种规划算法，以便独立替换控制策略。
15. 作为实车用户，我希望程序在驱动前显示 `/cmd_vel` 订阅者、其他发布者、运动模式、预计时间和无 `/odom` 提示，以便在确认后才让小车运动。
16. 作为实车用户，我希望小车按照“转向、零速过渡、前进、停止”的顺序执行每个路径段，以便控制行为可观察、可调试。
17. 作为实车用户，我希望系统发现其他节点正在发布 `/cmd_vel` 时阻止默认启动并要求确认，以便避免商家功能节点抢占控制。
18. 作为实车用户，我希望小车完成任务、发生异常或收到 Ctrl+C 时都先发送零速度，再退出，以便避免小车失控继续运动。
19. 作为实车用户，我希望重复按下 Ctrl+C 或遇到 shutdown 异常不会破坏停车动作，以便退出流程具备幂等安全性。
20. 作为普通用户，我希望路径预览同时承担路径接受确认，以便不再关闭窗口后重复输入一次确认。
21. 作为普通用户，我希望任务完成后可以使用相同地图和起终点重跑，以便快速测试不同参数。
22. 作为普通用户，我希望任务完成后可以只更换算法、只重新做路径后处理、重新选点、切换地图或退出，以便按最小范围重复工作。
23. 作为无显示器用户，我希望通过命令行提供地图、起点和终点并保存预览图片，以便在容器或远程终端运行。
24. 作为故障排查者，我希望模块失败后得到模块、阶段、输入、原因和建议动作，以便不依赖零散终端输出定位问题。
25. 作为故障排查者，我希望失败批次保留日志、错误 JSON 和已成功的阶段结果，以便从失败阶段重试而不重复建图。
26. 作为论文实验人员，我希望保存原始路径、平滑路径、最终路径段和统一指标，以便生成可复现的实验材料。

## Implementation Decisions

### 模块边界

- 当前能力分组为地图处理、路径规划、路径后处理和运动控制；这些分组允许增加或拆分，不得作为不可变的全局清单。
- 每个模块及其内部子模块提供独立 Python API 和 CLI，并只通过声明的输入输出契约通信。
- 顶层调度器负责创建运行批次、按阶段调用模块、更新批次状态和呈现错误，不直接访问模块内部类、全局变量或隐式当前工作目录。
- 规划器负责搜索候选路径；路径后处理器负责平滑、离散化、碰撞复核和分段；运动控制器只执行验证通过的路径段，不重新规划或静默修改路径。

### 运行批次和 JSON 契约

- 每次执行使用独立的 `run_id` 和运行目录，保存各模块的输入、输出、参数、日志、状态和错误。
- 所有模块结果包含 `schema_version`、`status`、`module`、`run_id`、`inputs`、`outputs`、`parameters`、`errors` 和创建时间。
- 地图数据、起终点、原始路径、平滑路径、路径段、规划指标和模块清单全部使用 JSON 表达；数组必须记录维度、坐标含义、单位和数据类型。
- 地图坐标统一使用 `row/col`；像素坐标只在地图处理模块内部使用。`row` 增大表示向南，`col` 增大表示向东。
- 物理距离使用米，速度使用 m/s，角速度使用 rad/s，方向角和转向角使用度，时间使用秒。
- 下游模块拒绝读取 `status` 不是 `success` 或缺少契约版本的结果，不生成看似成功的部分文件。
- 当前没有历史数据需要兼容，旧 TXT、NPY、NPZ 文件契约直接被新 JSON 契约取代。

### 路径后处理

- 第一版实现可替换的平滑器接口，当前平滑器为自行编写的分段三次样条。
- 自研样条使用自然边界条件和累计弧长参数化；生成曲线后以不超过 `0.25 * grid_size` 的间距采样。
- 采样点和连接线执行基础碰撞复核；起点、终点、避障约束和最大路径段长度必须保持有效。
- 平滑失败、点数不足、数值异常或曲线越界时回退到已验证原始路径，并在 JSON 中标记回退原因。
- 路径段至少包含段编号、起点、终点、行列位移、方向角、转向角、栅格距离、物理距离、预计时间和运动类型。
- 路径段超过配置的最大长度时再次分解，控制器接收分解后的结果。
- A*、Dijkstra、PRM、RRT 和 RRT* 的输出统一经过同一后处理器，以保证算法比较和控制边界一致。

### 运动控制

- 默认运动方式为 `turn`：计算路径段方向和最短转角，原地旋转，发布一个控制周期的零速度，再以 `linear.x` 前进并停止。
- 初始车头默认为地图正北；车头方向和速度映射由配置声明，不能隐藏在算法实现中。
- 速度命令发布到绝对 `/cmd_vel`，类型为 `geometry_msgs/msg/Twist`；当前底盘节点为 `/mecanum_chassis_node`。
- 没有 `/odom` 时使用经验速度和 timer 估算段持续时间；经验值初始约为 `0.30 m/s`，只作为粗略跟随依据，日志必须明确标记为开环。
- 将来接入 `/odom` 或其他反馈时，只替换段完成判断能力，不改变规划器、路径后处理器或 JSON 契约。
- 运动控制启动前检查 `/cmd_vel` 订阅者和发布者，列出商家控制节点；检测到其他发布者时默认阻止启动，用户确认后才继续。
- 任何任务完成、异常、Ctrl+C 或节点销毁路径都先重复发布零速度并完成通信缓冲，再销毁节点；ROS2 shutdown 只能执行一次且必须幂等。
- 商家示例的 `linear.x/y`、`angular.z` 语义作为实车接口参考；漂移动作不属于默认路径循迹能力。

### 交互流程

- 普通模式使用默认算法、默认栅格宽度和默认 `turn` 模式，仅保留地图/起终点选择、路径预览确认和驱动前安全确认。
- 研究模式支持多算法选择、参数覆盖、随机种子、指标比较和可视化，但默认不直接驱动车。
- 图形选点只接受起点和终点两个点击；第三次点击提示重置。R 清空，右键撤销最近点击，Enter 确认，Esc 取消。
- 起终点落在障碍格时保留错误提示并要求重新选择，不自动移动到最近空闲格。
- 栅格预览、路径预览和所有重要状态集中展示，预览确认不再配套额外终端确认。
- 无显示器模式通过显式参数提供起点和终点，不等待鼠标输入；预览保存为运行批次中的图片或 JSON 结果。
- 任务完成菜单支持相同路径重跑、更换算法、重新后处理、重新选择起终点、切换地图和退出；同一交互批次内不重复要求已确认输入。
- 运动执行期间只处理 Ctrl+C，不处理普通菜单键，不提供无 `/odom` 条件下的暂停续跑。

### 错误反馈和恢复

- 每个阶段产生 `result.json`；失败时额外产生结构化错误记录和日志，并更新运行批次清单。
- 交互模式在普通模块失败后暂停并提供重试、修改参数后重试、返回上一步或退出；只有安全相关错误或用户主动退出才终止整个系统。
- 批处理模式记录失败、跳过后续阶段并返回非零状态，不启动运动控制。
- 已完成阶段不可被失败重试覆盖；重试使用新的子批次或版本化输出。
- 进度反馈包含当前阶段、模块、路径段进度、预计剩余时间、是否使用开环和错误建议，并同步写入日志。

### 实验与指标

- 所有规划算法记录是否找到路径、规划耗时、原始节点数、原始路径长度、平滑后路径长度、转弯次数、预计执行时间、可计算时的最小障碍距离、算法参数和随机种子。
- 保存原始路径、平滑采样路径、最终路径段和统一可视化；可视化不参与控制逻辑，无显示器时只保存文件。
- 随机规划算法必须显式接受并记录随机种子。

## Testing Decisions

- 测试优先验证外部行为和模块契约，不测试私有实现细节；仓库当前没有既有测试框架，第一阶段建立独立的 Python 测试入口。
- 最高测试接缝是模块 CLI 与 JSON 契约：使用固定输入运行单模块，验证成功输出、版本、状态、字段、单位和下游可读取性。
- 地图处理测试覆盖坐标映射、起终点校验、障碍格拒绝和无显示器参数输入。
- 规划测试覆盖五种算法的统一结果结构、无路可达状态、随机种子复现和指标记录。
- 路径后处理测试覆盖自然边界样条的基本形状、累计弧长参数化、离散采样、起终点保持、碰撞复核、最大段长分解和失败回退。
- 运动控制测试使用 Fake ROS2 发布器，验证 `/cmd_vel` 的 `Twist`、角度方向、转向/零速/前进状态顺序、timer 时长、安全停车和重复 shutdown 不影响停车。
- 顶层集成测试使用固定地图和运行批次，验证四个阶段串联、manifest 状态、错误暂停、失败重试和不启动后续运动。
- 实车验证不作为自动化测试，只做低速前进、后退、左移、右移、90 度转向、路径段跟随和 Ctrl+C 停车验收。
- 实车测试前必须停止或隔离其他 `/cmd_vel` 发布者，并记录底盘节点、实际方向、经验速度和停车结果。

## Out of Scope

- 本规格不要求当前阶段接入 `/odom`、编码器或完整定位系统；没有这些反馈时不宣称精确闭环。
- 不实现麦轮四轮电机 PWM 或轮速逆解；底盘驱动节点负责从 `Twist` 到电机的底层转换。
- 不进行厘米级距离、速度、加速度或横移精确标定。
- 不把漂移、视觉循迹、障碍物实时避让或云台控制加入默认路径执行。
- 不要求第一版样条平滑参数达到研究最优，也不在本规格内切换成熟样条库。
- 不自动关闭商家控制节点，不接管系统级 `/cmd_vel` 仲裁。
- 不保留旧 TXT、NPY、NPZ 文件格式或旧固定目录的兼容层。
- 不在运动中提供无反馈条件下的暂停恢复或从中断点自动续跑。
- 不把旧的交互设计文档中的默认 mecanum、YAML 配置回写和重复确认流程视为当前规范。

## Further Notes

- 实际部署环境是 Raspberry Pi 宿主机 Debian 12、`aarch64`，Docker 镜像 `turbopi:new`，容器内 Ubuntu 22.04.4、ROS2 Humble、Python 3.10.12。
- 容器内 ROS2 setup 脚本目前引用不存在的 `/home/ubuntu/setup.sh`；该环境问题需要单独修复或在启动流程中显式处理，但不应通过业务代码静默掩盖。
- 当前底盘存在多个商家功能节点发布 `/cmd_vel`，运动控制预检和人工确认是第一版安全边界。
- 当前 `linear.x=0.5` 持续约 1 秒前进约 0.30 m，只是一次经验测量；速度配置必须允许后续重新标定。
- 这份规格取代旧的交互优化方案和旧文件契约；实现时应以本规格、`CONTEXT.md` 及已接受 ADR 为准。
