# SIT_LJGH_PROJECT 整体程序介绍与使用手册

> 本文描述当前实现的使用方式。模块通过统一 JSON 契约独立运行，顶层入口负责模式选择、批次调度、错误恢复和运动门禁。

核对日期：2026-11-14。软件链路已实现并留有 Fake ROS2 历史验收成功记录；真实底盘方向、旋转速度、路径跟随与停车仍需现场记录确认。本文运行示例均从项目根目录执行，实车命令在 `turbopi` 容器内执行。

## 一、程序做什么

本项目研究“地图图片 → 栅格地图 → 路径规划 → 路径后处理 → TurboPi 小车循迹”的完整流程。核心研究对象是 A*、Dijkstra、PRM、RRT、RRT* 等规划算法；小车控制只承担稳定、可观察的基本跟随，不追求厘米级精度。

实际运行环境为：Raspberry Pi 宿主机 Debian 12、`aarch64`，Docker 镜像 `turbopi:new`，容器内 Ubuntu 22.04.4、ROS2 Humble、Python 3.10.12。

## 二、整体设计

当前能力分为四个可扩展模块：

1. **地图处理**：读取图片、二值化、栅格化、选择起点和终点，输出带物理尺度的地图 JSON。
2. **路径规划**：在栅格地图上运行一个或多个算法，输出原始路径、随机种子和实验指标。
3. **路径后处理**：使用自研分段三次样条做基础平滑，再采样、碰撞复核和最大段长分解，输出控制器可执行的路径段。
4. **运动控制**：读取路径段，按“原地转向 → 零速过渡 → `linear.x` 前进 → 停止”控制 TurboPi。

这些是当前能力分组，不是永久固定的模块清单。新增定位、避障、里程计或其他研究内容时，应增加独立模块，通过 JSON 契约接入。

## 三、数据和运行批次

每次实验拥有独立的 `run_id`。运行目录保存各阶段的 JSON 输入、输出、参数、日志、预览和状态清单。`runs/` 属于本地生成物，已加入 Git 忽略规则；历史生成物于 2026-11-14 移出仓库，新克隆的项目需要重新运行生成结果。

所有模块结果至少包含：

- `schema_version`
- `status`
- `module`
- `run_id`
- `inputs`
- `outputs`
- `parameters`
- `errors`
- 创建时间

地图坐标使用 `row/col`，地图上方为北、下方为南、左方为西、右方为东。物理距离使用米，速度使用 m/s，角速度使用 rad/s，时间使用秒。

## 四、普通模式使用流程

普通模式面向一次实车任务，减少不必要的输入：

1. 选择地图。交互终端中即使只有一张图片也会列出并询问编号，直接回车使用第一张；直接传图片路径或非交互模式不会询问。
2. 在地图窗口点击一次起点、一次终点。
3. 按 Enter 确认；R 重置，右键撤销，Esc 取消。
4. 使用配置中的默认栅格宽度和默认算法。
5. 系统完成规划、路径后处理和可视化。
6. 在路径预览中确认原始路径、平滑路径、执行段和预计时间。
7. 驱动前检查 `/cmd_vel`、底盘订阅者和其他发布者。
8. 用户确认后，按路径段执行 `turn` 模式。
9. 任务完成后选择重跑、更换算法、重新后处理、重新选点、切换地图或退出。

起点或终点落在障碍格时，系统要求重新选择，不会静默改点。

普通模式 CLI 示例：

```bash
python main.py map_pipeline/data/input/room-16room_000.png \
  --headless --start 313,424 --goal 311,427 --no-drive
```

### 现场照片透视矫正

主实验输入目录已改为公开基准地图。下面的 `photos/site.jpg` 是用户另行提供的现场照片路径示例，仓库不提供该照片；公开基准 PNG 不需要透视矫正。

直接俯拍的照片通常包含透视、旋转、桌面背景和纸张接缝，直接栅格化会让地图范围和场景不一致。使用 `--rectify` 先做四点透视矫正和裁剪：

```bash
python main.py photos/site.jpg \
  --headless --no-drive \
  --rectify \
  --corners "35,15;1225,15;1225,1420;35,1420" \
  --arena-width-m 2.0 \
  --grid-size-m 0.05 \
  --start 5,5 --goal 25,25
```

- `--corners` 是原图像素坐标，四个角点用 `;` 分隔；程序会自动排序为左上、右上、右下、左下。
- 不提供 `--corners` 时：有图形界面会打开四角点击窗口；只有终端时依次提示四个 `x,y`。
- `--arena-width-m` 给出场地真实宽度，程序按 `grid_size` 反算网格列数，并用真实宽度校准每个栅格的物理尺寸。
- `--grid-size-m` 覆盖配置中的栅格边长；例如 2 m 宽场地、5 cm 栅格 → 40 列。
- 矫正后的图片保存在运行目录的 `*_rectified.png`，结果 JSON 的 `outputs.rectification` 保存源角点、单应矩阵、输出尺寸和米/像素；`outputs.rectified_image` 指向矫正图。
- 纸张接缝、小噪点可以通过 `map_pipeline/config.yaml` 的 `min_obstacle_area_px` 和 `morphology_kernel` 清理。

使用 `--rectify` 时，`--start-px/--goal-px` 仍按原图像素坐标填写，程序会自动通过单应矩阵转换到矫正图；`--start/--goal` 则直接使用最终栅格坐标。

## 五、研究模式使用流程

研究模式用于算法实验，不默认驱动车：

1. 选择地图和起终点。
2. 选择多个规划算法或覆盖算法参数。
3. 为随机算法指定并记录随机种子。
4. 运行统一规划、路径后处理和指标统计。
5. 查看原始路径、平滑路径、分段路径和算法对比结果。
6. 将实验结果保存在独立运行批次中。

研究模式默认只生成比较结果。需要实车执行时，应针对选定算法单独规划和后处理，再经过驱动前安全确认。当前控制器不直接读取多算法比较数组中的路径段。

研究模式 CLI 示例：

```bash
python main.py map_pipeline/data/input/room-16room_000.png \
  --mode research --headless --start 313,424 --goal 311,427 \
  --algorithms astar,dijkstra --seed 42
```

## 六、无显示器运行

无显示器时，使用命令行明确提供地图和起终点，不等待鼠标输入。预览保存到当前运行批次，缺少起点或终点时报告参数错误，不自动猜测。

支持三种方式：

1. 显式提供栅格坐标：

```bash
python main.py map.png --headless --start 313,424 --goal 311,427 --no-drive
```

2. 在终端输入起终点：

```bash
python main.py map.png --headless --select-terminal --no-drive
```

程序会先打印栅格行数、列数和栅格边长，并保存一张无起终点标记的预览图；随后依次提示输入 `起点 row,col` 和 `终点 row,col`。格式错误、越界、障碍格和起终点相同都会重新提示，直接回车取消。`--select-terminal` 要求 stdin 和 stdout 都是交互式终端。

3. 自动检测：有交互终端但未检测到图形显示时，主入口会自动切换到终端选点；如果 stdin/stdout 不是终端，则必须显式提供 `--start/--goal`，避免脚本挂起。

显式 `--headless` 驱动必须同时使用 `--drive --accept-path --yes`；当前实现不会在该模式下逐步询问路径和驱动确认。保持交互式终端且不加 `--headless`、使用 `--select-terminal` 并且没有图形显示时，路径接受和驱动确认才通过终端逐步询问。默认 headless 只保存预览并跳过运动控制。

## 七、TurboPi 运动控制约定

- 速度话题：绝对 `/cmd_vel`
- 消息类型：`geometry_msgs/msg/Twist`
- 底盘节点：`/mecanum_chassis_node`
- `linear.x > 0`：前进；`linear.x < 0`：后退
- `angular.z > 0`：左转；`angular.z < 0`：右转
- 初始车头：地图正北
- 当前执行器没有 `/odom` 订阅，始终使用 timer 开环；配置中的 `odom_topic` 尚未连接反馈
- `linear.x=0.5` 持续约 1 秒约前进 0.30 m，仅作为初始经验标定

运动控制启动前应停止或隔离商家的 `gesture_control_node`、`object_tracking`、`line_following`、`avoidance_node` 和 `qrcode`，避免多个发布者竞争 `/cmd_vel`。

## 八、安全退出

所有退出路径都遵循：

```text
先重复发布零速度 Twist
→ 等待通信发送
→ 停止定时器和销毁节点
→ 只调用一次 rclpy.shutdown()
```

Ctrl+C、运行异常、路径完成和节点销毁都必须停车。没有 `/odom` 时不支持暂停后从中断点自动续跑。

## 九、错误处理

普通模块错误会暂停当前运行批次，并显示：

- 发生错误的模块和阶段
- 输入和输出位置
- 错误类型与原因
- 建议动作

交互模式用户可以重试、修改参数后重试、返回上一步或退出；任务完成后可重跑、换算法、重新后处理、重新选点、换地图或退出。每次重试使用批次内的版本化结果路径，已成功阶段不会被失败尝试覆盖。运动控制错误必须先停车。headless/批处理模式记录失败并返回非零状态，不启动后续运动。

启动选图与完成菜单的 `m` 使用相同的地图列表，支持输入编号或自定义图片路径。无效输入会原地重选；启动时回车选第一张，换图时回车选当前地图并重新选点。输入 `b` 取消换图并返回完成菜单，保留原地图、起终点与已有结果，不触发模块重跑。确认新地图后重新选点，旧图的四角坐标也会清除；同一会话中的 `--no-drive` 始终有效。

地图阶段失败时，`r` 重试原输入，`m` / `b` 打开地图选择器；在选择器内输入 `b` 会回到恢复菜单。`p` 只修改栅格配置 YAML 文件路径，不能输入地图编号；路径不合法时重新提示，回车或 `b` 保留原配置。完成菜单和失败菜单中的无效选项都会重新提示。

换算法 `a` 会列出带说明的算法列表，可输入编号、名称或逗号分隔的多个选项（例如 `1,2`）；回车或 `b` 返回菜单，保留原算法、参数和结果。多个选项进入研究模式并禁用驱动。算法列表读取规划配置中的 `available_algorithms`，名称来自注册表；换成不同算法时清除上一算法的临时参数，使用各算法的配置默认值。

规划阶段失败时，`a` / `b` 返回算法列表，不重新建图；选择器取消后回到恢复菜单。规划与后处理参数必须输入 JSON 对象，例如 `{}` 或 `{"smooth": false}`；数字 `1`、数组和错误 JSON 会原地提示重输，不会污染当前参数；输入 `b` 取消也不会触发重试。Windows 中文路径的预览采用字节读取与 OpenCV 解码，避免 `imread` 无法打开已存在文件。

Windows 下 `manifest.json` 或模块结果被短暂占用时，JSON 原子写入会使用独立临时文件，并对替换时的 `PermissionError` 在最多 1.25 秒内重试。持续失败会保留原文件及完整的待保存文件，顶层保存错误提示包含实际目标与候选文件路径；不要删除原文件绕过锁定。该机制不能合并多个进程对同一运行批次的修改。启动选图时按 `Ctrl+C` 会输出取消提示并以 130 退出，不启动模块；运动中的退出仍遵循先停车再退出。重新选择当前默认算法会保留临时参数。

## 十、开发与验收顺序

实现按本地票据的依赖顺序推进：

```text
01 契约基础
├── 02 地图处理
├── 03 规划器
└── 04 路径后处理
    └── 05 运动控制
        └── 06 顶层交互与恢复
            └── 07 全流程与实车验收
```

自动化测试优先使用模块 CLI、JSON 契约和 Fake ROS2 发布器；实车只做低速方向、转向、路径跟随和安全停车验收。实现细节、硬件边界和已确认的 ADR 见 `AGENTS.md`、`CONTEXT.md` 与 `docs/agents/`。

## 十一、当前实现限制与配置核对

- **物理尺度**：地图默认 512 列、每格 1.0，保持 Moving AI 原始栅格；1.0 是离线尺度约定，JSON 虽以米表达，仍不代表真实物理标定。真实场地应设置尺度，核对地图 JSON 的 `outputs.map.grid_size_m`，再判断路径距离。
- **车体通行能力**：碰撞复核检查路径点及连线对应的障碍栅格，目前没有明确的车体轮廓和障碍膨胀配置；路径中心线可通行不能证明整车可通过。
- **预计时间**：后处理默认 `turn_speed_rad_s=2.0`，控制器默认 `turn_speed=1.0`，执行器按运动配置重新计算运动时长并插入零速过渡。预览时长不等于实际执行时间。初始朝向也分别来自后处理和运动配置，运行前应保持一致。
- **算法比较**：A*、Dijkstra 使用四邻域，PRM、RRT、RRT* 可以连接斜向视线边；路径长度比较需记录这种差异，有限迭代结果不能作为全局最优保证。
- **研究模式失败**：只要有一个算法失败，规划结果整体就是 `failed`；成功算法结果仍保留在比较数组里，但下游拒绝继续。可仅选择成功算法重跑。
- **研究结果驱动**：多算法后处理将路径段保存在 `outputs.comparisons[*].outputs.segments`；控制器只读取顶层 `outputs.segments`。实际驱动应针对选定算法单独规划和后处理。当前顶层虽接受研究模式 `--drive`，但不能据此直接执行多算法结果。
- **实验指标**：已记录规划耗时、节点数、路径长度、后处理段数、预计时间和回退情况。正式规格中的转弯次数及最小障碍距离尚未作为统一指标输出。
- **基础地图 API**：`MapPipeline` 仅覆盖基础建图；透视矫正、噪点清理和列数按图宽限制属于 JSON CLI 流程，不能假设两个入口支持全部相同配置。

## 十二、验证状态

执行 `python -m unittest discover -s tests -q` 可运行软件测试，`python tools/acceptance.py` 可运行固定地图与 Fake ROS2 软件验收。运行前需在所用 Python 环境安装 `numpy`、`opencv-python`、`pyyaml`；实车 ROS2 Python 包以容器环境为准。

2026-11-14 更换公开地图后，项目独立 `.venv` 中的 136 个软件测试通过；12 张 PNG 的实际建图结果与官方 `.map` 逐格一致，文件 SHA-256 校验通过。三类地图各取一张，用官方第一条任务运行 A*/Dijkstra 研究模式，建图、规划和后处理全部成功，未驱动实车。这是接入冒烟验证，不代表完整基准实验或实车验收。实车待办见 `.scratch/path-planning-control-redesign/issues/07-full-workflow-real-vehicle-acceptance.md`。

完整非真机验收、复现命令、默认采样算法失败观察及清理范围见 [2026-11-14 验收记录](verification/2026-11-14-offline.md)。
