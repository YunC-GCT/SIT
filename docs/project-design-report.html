01项目定位与目标

大创项目：以路径规划算法研究为核心，同时让 TurboPi 小车完成稳定、可观察的基本循迹。

核心链路

地图图片 → 栅格地图 → 路径规划 → 平滑/复核/分段 → ROS2 循迹。

图片→栅格 JSON→原始路径 →执行段→Twist

设计目标

  • 五种规划算法可替换、可比较、可复现实验
  • 模块独立运行，同时提供 Python API 和 CLI
  • 所有阶段通过版本化 JSON 契约连接
  • 普通模式少交互，研究模式多算法、多指标
  • 任何退出路径先停车，再关闭 ROS2
当前阶段：软件链路和自动化验收已完成，处于“实车验收前”。剩余工作集中在树莓派实车的方向、转向、路径跟随和停车验证。

02系统架构

顶层负责调度和错误反馈，四个能力模块通过 JSON 文件解耦；运动控制只读取已验证路径段。

数据流

阶段输入输出关键约束
map_pipeline图片、栅格配置、起终点/四角地图 JSON、预览、矫正图row/col 坐标；障碍格拒绝；无显示器可终端输入
path_planner地图 JSON、算法、参数、种子原始路径 JSON、指标、比较结果五种算法统一输出；随机算法记录 seed
path_postprocess地图 JSON、原始路径 JSON平滑路径、执行段 JSON、指标平滑失败回退；碰撞复核；段长上限
motion_control执行段 JSON/cmd_vel Twist、执行报告只读 success 结果；预检；先停车再退出

3.1 map_pipeline 内部架构

图片按需先做四点透视矫正，再二值化、清理和栅格化。顶层统一选图，地图交互层负责起终点和四角，处理层接收已确认坐标。

交互分支：显式坐标 / --select-terminal / Tk/OpenCV 两点选点 / 四角窗口。输出可附带 preview、rectified_image 和 rectification。

3.2 path_planner 内部架构

地图 JSON 先经过输入校验，再由注册表创建算法；规划结果统一归一化后输出路径和指标。研究模式复用同一入口跑多个算法。

研究模式输出 outputs.comparisons[]；随机算法必须记录 seed。

3.3 path_postprocess 内部架构

原始路径先平滑，再离散采样和碰撞复核；最后按固定弧长归一化执行段，使 A* 与采样算法的停车次数趋同。

平滑失败、点数不足、数值异常、曲线越界或弦穿过障碍时，回退到已验证路径并记录 fallback / fallback_reason，不把失败伪装成平滑成功。

3.5 模块之间实际传递的 JSON

链路传递方式下游读取的字段上游写入
map_pipeline → path_planner --map-result <path> outputs.map.grid.values、grid_size_m、start、goal 地图 JSON + 预览 / 矫正产物
path_planner → path_postprocess --planner-result <path> outputs.raw_path.points.values 或 outputs.comparisons[].raw_path 原始路径、指标、算法参数、seed
path_postprocess → motion_control --postprocess-result <path> outputs.segments、parameters.grid_size_m、parameters.initial_heading 执行段、平滑信息、指标
motion_control → ROS2 /cmd_vel 绝对话题 Twist.linear.x/y、Twist.angular.z ROS2 消息（不是 JSON 文件）
orchestrator → 模块 CLI 子进程 + --output / --run-id status、module、run_id、errors manifest 阶段状态与版本化 result 路径
模块 CLI 之间通过文件路径和 JSON 通信。require_success() 校验契约、成功状态和可选模块名；顶层调度器另外校验结果的 run_id。失败结果不会覆盖已有成功结果。
模块边界不是永久清单。新增定位、避障、里程计等能力时，增加独立模块并通过 JSON 契约接入，不改已有模块内部实现。

06ROS2 运动控制协议

当前没有 /odom，采用 turn 模式 + timer 开环估算；控制目标是稳定、可观察，不宣称厘米级精度。

Twist 字段

字段含义本项目用法
linear.x底盘 X 前方速度前进命令值 0.5
linear.y底盘 Y 左方速度当前 turn 模式不使用
angular.z绕 Z 轴角速度原地转向，符号按底盘坐标系

话题：绝对 /cmd_vel；类型：geometry_msgs/msg/Twist；底盘订阅者：/mecanum_chassis_node。

每段执行顺序

turn      原地旋转到段方向（180° 拆成两个 90°）
zero      发布一个周期的零速 Twist
forward   沿车头方向前进 distance_m
zero      段结束零速过渡
stop      任务/异常/退出时重复零速并等待通信缓冲

开环距离估算

// 当前经验值：linear.x=0.5 持续约 1 s 前进约 0.30 m
empirical_forward_speed ≈ 0.30 m/s
target_ticks = cumulative_distance / empirical_forward_speed / timer_period
published_distance ≈ published_ticks × timer_period × empirical_forward_speed

控制周期 0.1 s；整段控制周期跨段累计，避免“每段各自取整”导致总距离随段数变化。没有里程计闭环，实际距离会受负载、电量、地面和启动延迟影响。

安全门禁：启动前检查 /cmd_vel 订阅者和其他发布者；发现其他速度发布者时默认阻止启动。必须停用商家的 gesture_control、object_tracking、line_following、avoidance、qrcode 等功能。
退出：Ctrl+C、SIGTERM、SIGHUP、异常、完成和节点销毁都先重复发布零速度并等待通信缓冲，再销毁节点、幂等 shutdown。停车发布失败会记录警告并保持 stopped=False，不会误报已安全停车。

07交互设计

普通模式只保留必要确认；研究模式开放多算法与指标；无显示器时退化为终端输入。

普通模式

GUI 选点、路径预览确认、驱动前 yes；任务完成后可重跑、换算法、重新后处理、重新选点、换图或退出。

无显示器

显式提供 --start/--goal，或 --select-terminal 在终端输入；路径预览用 yes 确认；无人值守加 --accept-path。

研究模式

一次运行多个算法，记录参数、随机种子和统一指标；默认不驱动车。当前运动 CLI 只接受单算法顶层路径段，需针对选定算法单独规划、后处理并确认后执行。

换算法展示编号、说明与名称，支持单选或逗号多选；回车 / b 取消。规划失败用 a / b 回算法列表，保留地图；换算法时清除旧临时参数。规划/后处理参数只接受 JSON 对象，错误输入原地重输；取消不触发重试。Windows 路径预览通过字节读取与 imdecode 支持中文目录。

完整终端提示、窗口按键和纯终端流程见 交互形式说明。

08错误恢复与安全退出

模块失败

  • 返回模块、阶段、输入、原因、建议动作
  • 交互模式暂停并提供重试、改参数、返回、退出；地图失败支持重新选图，b 回到地图选择；规划失败用 a / b 回算法列表
  • 批处理/headless 返回非零状态，不启动后续阶段
  • 已成功阶段不被失败重试覆盖，使用版本化输出

安全退出

Ctrl+C / SIGTERM / SIGHUP / 异常 / 完成
→ 发布零速度 Twist（重复 N 次）
→ 等待通信缓冲
→ 销毁节点
→ 幂等 rclpy.shutdown()
硬杀进程、断电和容器被强制销毁无法执行停车。实车运行建议放在 tmux/screen 中，并保留人工急停；不要用 Ctrl+Z 挂起控制进程。
Windows 文件保存与取消：运行记录和模块结果使用独立临时文件后原子替换；遇到短暂 PermissionError 时最多等待 1.25 秒重试。持续失败时保留原 JSON 和待保存文件并报告实际保存路径，不把错误归咎于地图输入。此机制不支持多个进程并发修改同一批次。在启动选图时 Ctrl+C 简短退出（130），尚未运行运动模块；运动中仍沿用先停车再退出。重新选择当前默认算法会保留临时参数。

10可选优化与路线图

按“实车安全 → 使用体验 → 工程质量 → 研究扩展”排序。

优先级优化项为什么建议动作
P0 完成实车验收 软件验收不能替代真实方向、转向和停车验证 隔离其他 /cmd_vel 发布者；低速前进/后退/左右转/90°；记录 manual_record.json
P0 标定经验速度与转向速度 0.30 m/s 只来自一次前进测量，横移/转向未标定 相同电量、地面、负载下重复 3 次；分别记录 linear.x/y、angular.z
P0 完善实车运行手册 SSH 断线、Ctrl+Z、容器销毁都可能绕过停车 固定 tmux 流程、启动前检查、人工急停、停止其他商家节点
P1 统一 GUI 选点后端 两点选点优先 Tk，四角选点仍用 OpenCV，Windows DPI 下可能偏移 补 Tk 四角窗口或统一窗口后端；保留 --corners 作为可靠后备
P1 统一地图选择与菜单恢复（已完成） 启动与换图支持相同编号/路径规则，无效输入不退出 取消保留原结果；地图失败可重选；--no-drive 在换算法后继续有效
P1 运动中显示紧凑进度 当前只有逐段 ROS 日志，长路径缺少整体进度 输出“段 i/N、已走距离、预计剩余、open-loop”单行进度
P1 依赖锁定与 CI 已有 requirements.txt / requirements-dev.txt；版本范围仍可能产生环境差异 记录验证环境并按需锁定依赖；CI 运行 unittest、pyflakes、pyright 与覆盖率检查
P1 栅格化性能 create_grid_map 为 Python 双循环，高分辨率地图会变慢 用积分图或 cv2.resize 向量化；增加图像尺寸上限
P2 接入 /odom 闭环 timer 开环距离受负载和地面影响 只替换“段完成判断”能力，不改 JSON 契约和规划/后处理
P2 自动四角检测 人工点四角可靠但慢；当前照片自动检测会退化成整图 先做白纸/场地边界检测，再让人工确认；失败时回退手动角点
P2 研究指标与对比 目前有耗时、节点数、路径长度、预计时间 增加转弯次数、最小障碍距离、平滑度、成功率；生成算法对比报告
P2 平滑器适配库 当前为自研自然边界三次样条 保留 PathSmoother 接口，后续接成熟样条库，不改后处理流程
P2 清理遗留入口 run_pipeline.py / MapPipeline 与新主流程并存 明确弃用或只保留文档入口，减少重复交互和测试面

11运行方式与部署

常用命令

# 普通模式：显式坐标，无显示器
python main.py map.png --headless \
  --start 313,424 --goal 311,427 --no-drive

# 终端交互选点
python main.py map.png --headless --select-terminal

# 现场照片矫正
python main.py photo.jpg --headless --no-drive \
  --rectify --corners "35,15;1225,15;1225,1420;35,1420" \
  --arena-width-m 2.0 --grid-size-m 0.05 \
  --start 5,5 --goal 25,25

# 研究模式
python main.py map.png --mode research --headless \
  --start 313,424 --goal 311,427 --algorithms astar,rrt --seed 42

# 软件验收
python tools/acceptance.py

实车部署

项值
宿主机Raspberry Pi Debian 12 / aarch64
容器turbopi:new
容器内系统Ubuntu 22.04.4 LTS
ROS2Humble
Python3.10.12
项目路径/home/ubuntu/SIT_LJGH_PROJECT
底盘节点/mecanum_chassis_node
# 树莓派宿主机
docker cp /home/pi/SIT_LJGH_PROJECT turbopi:/home/ubuntu/
docker exec -it turbopi bash

# 容器内
cd /home/ubuntu/SIT_LJGH_PROJECT
ros2 topic list
ros2 topic info /cmd_vel
驱动前必须确认 /cmd_vel 只有一个控制发布者，底盘订阅者存在；无显示器驱动需要 --drive --accept-path --yes，且不应在未检查预检信息时使用。
