# 领域文档

本文规定工程技能在探索和修改本仓库前应如何使用领域文档。

## 探索前读取

- 若根目录存在 `CONTEXT.md`，先读取它。
- 若根目录存在 `CONTEXT-MAP.md`，它会指向各上下文的 `CONTEXT.md`；读取与当前任务相关的文件。
- 读取 `docs/adr/` 下与当前工作相关的架构决策记录。
- 若上述文件或目录尚不存在，静默继续，不要将缺失本身报告为问题，也不要提前建议创建。

`/domain-modeling` 会在术语或决策真正得到澄清时按需创建这些文档，通常由 `/grill-with-docs` 或 `/improve-codebase-architecture` 调用。

## 文档布局

本仓库采用单上下文布局：

```text
/
|-- CONTEXT.md
`-- docs/
    `-- adr/
```

只有将来项目演变为大型多包仓库，并在根目录引入 `CONTEXT-MAP.md` 后，才使用各上下文独立的 `CONTEXT.md` 与 ADR 目录。

## 使用统一词汇

Issue 标题、重构建议、诊断假设和测试名称中出现领域概念时，应使用 `CONTEXT.md` 定义的术语，不要改用其中明确排除的同义词。

若需要的概念尚未出现在词汇表中，应先判断它是脱离项目语言的新造词，还是需要通过 `/domain-modeling` 补齐的真实领域空缺。

## 标明 ADR 冲突

若拟议工作与现有 ADR 冲突，必须明确指出冲突及理由，不得静默覆盖已有决策。
