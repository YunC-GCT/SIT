# 规划后处理与控制执行分离

状态：accepted

本项目将规划器、路径后处理器和运动控制器分成三个边界：规划器输出原始路径，后处理器负责平滑与多段分解，运动控制器只执行已验证的路径段。由于当前系统没有 `/odom`，第一阶段的段完成判断采用可配置的经验速度与时间估算，并保留安全超时和后续接入里程计的边界；这样优先保证多种路径规划算法能够驱动小车完成可观察的路径跟随，而不把暂时缺少反馈的问题伪装成精确闭环。

## 考虑过的方案

- 让运动控制器自行平滑、改写或绕障：拒绝，因为会混淆算法研究结果与执行层行为。
- 在没有 `/odom` 时阻止实车执行：拒绝，因为当前项目的主要目标是验证路径规划算法和基本跟随能力；执行层可先采用明确标注的开环估算。
