# 模块独立与路径后处理边界

状态：accepted

本项目将建图、路径规划、路径后处理和运动控制作为可独立运行的四个大模块，通过文件或明确的数据契约单向连接；每个大模块内部的子模块也遵守同样的边界。规划器只产生候选路径；路径后处理器第一版完成自行实现的分段三次样条平滑、离散化、最大段长限制和基本碰撞复核，复杂参数优化留给后续研究；运动控制器只执行复核通过的路径段。这样算法研究者可以替换某一个模块或新增模块，而不需要改动其他模块的内部逻辑。

## 考虑过的方案

- 在运动控制器内部平滑或重规划：拒绝，因为会把规划算法结果与底盘执行策略耦合，难以比较和独立测试。
- 让各规划算法分别实现自己的平滑逻辑：拒绝，因为会产生重复实现并使不同算法的结果无法使用统一的执行边界。

## 后果

模块之间必须稳定记录输入输出格式、坐标约定和失败语义。新增路径后处理算法或控制反馈方式时，应通过同一契约接入，而不是直接读取或修改其他模块的内部状态。

第一版路径后处理以“可运行、可验证、可替换”为目标，不追求样条参数或碰撞采样密度的最终最优；任何研究级优化都应在不破坏既有契约的前提下独立演进。
