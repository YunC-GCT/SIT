# 交互批次与安全确认

状态：accepted

普通模式以最少必要交互完成一次实车任务：用户选择地图和起终点，系统使用默认算法完成规划、路径后处理和预览，经过一次驱动前安全确认后执行。研究模式单独开放多算法、参数和结果对比；运动中的唯一控制入口是 `Ctrl+C` 安全停车，任务完成后在同一交互批次内允许复用已确认的地图和起终点重跑。该设计取代旧交互方案中每次询问运动模式、重复终端确认和隐式记忆配置的做法。

## 交互边界

- 起终点是必须的人机交互：图形模式点击一次起点、一次终点，Enter 确认，R 重置，Esc 取消；障碍格不会被静默替换。
- 栅格宽度、默认算法和运动模式来自配置；只有用户主动调整或进入研究模式时才询问。
- 路径预览同时承担路径接受确认，展示原始路径、平滑路径、执行段、预计时间和无 `/odom` 的开环提示。
- 驱动前执行 `/cmd_vel` 预检，列出底盘订阅者和其他速度发布者；未得到确认不启动运动。
- 模块失败暂停当前批次并提供重试、改参数、返回上一步或退出；批处理模式记录失败并返回非零状态。
- 无显示器时使用显式命令行参数提供起点和终点，不自动猜测交互输入。

## 后果

普通演示和实车运行更少被研究选项打断，同时保留算法实验入口。没有 `/odom` 时无法提供暂停恢复或精确续跑，因此中断后只允许重新确认并重跑；所有阶段进度、错误和选择写入运行批次。
