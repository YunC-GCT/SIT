目前系统交互形式 一览

当前交互由“终端命令 + 图形选点/预览窗口 + 驱动前安全确认”组成。 本报告按一次普通模式的真实流程展示每一步会看到什么、要输入什么，以及无显示器时如何退化到纯终端。

主入口：main.py GUI：Tk / OpenCV 终端：stdin/stdout 安全确认：/cmd_vel 预检 + yes 报告日期：2026-11-03
流程概览 1 启动与选图 2 图形选点 3 四角矫正 4 路径预览 5 驱动前确认 6 完成/恢复菜单 7 纯终端流程 8 现状与注意

00一次普通模式的交互流程

普通模式面向一次实车任务：只保留选图、起终点、路径确认和驱动确认。

启动python main.py
选图终端编号或直接给路径
起终点GUI 点两次 / 终端输入
预览原始路径、平滑路径、执行段
驱动确认预检 /cmd_vel + 输入 yes
完成菜单重跑 / 换算法 / 退出
可选前置步骤：如果输入是俯拍照片而不是干净的正视地图，会在选点之前插入 --rectify 四角矫正与裁剪。它发生在“选图”和“起终点”之间。

01启动与选图

终端如果命令行没有给图片路径，程序会列出 map_pipeline/data/input 下的图片。

$ python main.py
Available maps:
  [1] 01_scattered.png
  [2] 02_maze.png
  [3] 03_narrow.png
  [4] 04_rooms.png
  [5] 05_spiral.png
  [6] 图1.jpg
Map number (blank uses first): 1

只要处于交互终端，就会始终列出图片并询问编号，即使只有一张也会询问；直接回车使用第一张。直接写图片路径或非交互模式时不会询问。图片路径也可以作为第一个位置参数传入。

$ python main.py map_pipeline/data/input/图1.jpg

02图形选点窗口

GUI有图形界面时，会打开 Tk（Windows 优先）或 OpenCV 窗口；只接受起点和终点两次点击。

┌─ Select Start & Goal ─────────────────────────────────────┐
│  S: grid=(2,2) FREE                                        │
│  G: grid=(37,37) FREE                                      │
│                                                            │
│        ███                 █████                           │
│   S ●                     ██        ████                   │
│         █████                  G ●                         │
│                                                            │
│ Select start, then goal (Enter=confirm, R=reset,           │
│ Esc=cancel)                                                │
└────────────────────────────────────────────────────────────┘
操作结果
左键 第 1 次设置起点，显示所在栅格与 FREE/OBSTACLE
左键 第 2 次设置终点；第三次点击提示先重置或撤销
Enter两点都已选且都在空闲格时确认
R清空起点和终点
右键撤销最近一次点击
Esc / 关闭窗口取消本次选点，记录为结构化失败
起点或终点落在障碍格时，窗口只提示并保留该点，不会自动移动到最近空闲格；必须重新点或撤销。

03四角透视矫正（可选）

GUI使用 --rectify 且没有给 --corners 时，会先打开四角选择窗口；有终端但无图形显示时改为逐个输入 x,y。

┌─ Select Arena Corners ─────────────────────────────────────┐
│                                                            │
│   ①──────────────────────────────────────────②             │
│   │                                          │             │
│   │            场地内部（物体=障碍）          │             │
│   │                                          │             │
│   ④──────────────────────────────────────────③             │
│                                                            │
│ Click 4 arena corners (Enter=confirm, R=reset,             │
│ right-click=undo, Esc=cancel)                              │
└────────────────────────────────────────────────────────────┘

也可以完全跳过窗口，直接用原图像素坐标指定：

$ python main.py map_pipeline/data/input/图1.jpg --headless --no-drive \
    --rectify \
    --corners "35,15;1225,15;1225,1420;35,1420" \
    --arena-width-m 2.0 --grid-size-m 0.05 \
    --start 5,5 --goal 25,25

纯终端、没有 --corners 时的提示：

原图尺寸: 1252 x 1465（x,y 像素坐标）
按任意顺序输入四个场地角点，程序会自动排序
第1个角 x,y: 35,15
第2个角 x,y: 1225,15
第3个角 x,y: 1225,1420
第4个角 x,y: 35,1420
矫正后会保存 *_rectified.png，并在结果 JSON 的 outputs.rectification 中记录四角、单应矩阵和尺度。 输入非法、越界或四点不构成凸四边形时会重新提示或报错，不会静默裁剪。

04路径预览确认

GUI规划与后处理完成后，会弹出路径预览；预览窗口本身就是“接受路径”的确认。

┌─ Path Preview ─────────────────────────────────────────────┐
│ segments=36  estimated=73.14s  open-loop                   │
│                                                            │
│    S ●──────┐                                              │
│             │        ████                                  │
│             └──────┐ ██                                    │
│                    │        █████                         │
│                    G ●                                     │
│                                                            │
│              原始路径 / 平滑路径 / 执行段                    │
└────────────────────────────────────────────────────────────┘

按 Enter、Space 或 y 接受；直接关闭窗口视为拒绝，流程以 PATH_ACCEPTANCE_REQUIRED 结束，不会启动小车。

无显示器但终端可交互时，预览确认退化为一句话：

路径预览已保存: runs/20261103T.../preview/path_preview.png
确认接受该路径？输入 yes 继续: yes

05驱动前预检与启动确认

终端安全门禁运动控制启动前会打印 /cmd_vel 的订阅者、发布者、运动模式和预计时间，然后要求输入 yes。

[Follower] 读取路径段: runs/.../path_postprocess/result.json
[Follower] 路径段数: 36
[Follower] 后处理参数: initial_heading=north
[Follower] 运动模式: turn, /odom 不可用时使用 timer 开环估算；经验速度只用于粗略时间控制。
[Follower] 后处理预计时间: 73.14s
[Follower] /cmd_vel 预检话题: /cmd_vel
[Follower] /cmd_vel 订阅者: ['/mecanum_chassis_node']
[Follower] /cmd_vel 发布者: ['/path_follower']
确认启动小车运动？输入 yes 继续: yes
情况行为
存在其他 /cmd_vel 发布者打印警告并拒绝启动；需先停用 gesture_control_node、object_tracking、line_following、avoidance_node、qrcode
未看到 /mecanum_chassis_node 订阅拒绝启动
输入不是 yes不驱动，记录为安全预检失败
无交互终端必须显式传 --yes；否则拒绝

运动执行期间按路径段依次输出状态：

[path_follower] segment 0 rotate 90.0deg: 1.57s
[path_follower] segment 0 zero transition: 0.10s
[path_follower] segment 0 forward 0.600m open-loop: 2.00s -> 20 ticks
...
[Follower] 执行完成: completed=True, commands=908, stopped=True
运动中按一次 Ctrl+C，程序会先重复发布零速度并等待通信缓冲，再退出。 不要按 Ctrl+Z（挂起进程，车可能保持最后一条速度命令），也不要直接关终端。

06完成菜单与错误恢复

任务完成

Task complete: rerun [r], change algorithm [a],
reprocess [p], reselect points [s], change map [m], quit [q]:
输入动作
r相同批次重跑
a更换算法（可逗号分隔多个）
p修改后处理参数后重跑
s重新选择起终点
m切换地图
q退出

模块失败

[top-level] path_planner execute:
input=... reason=... Suggestion: ...
Choose retry [r], edit parameters [p],
back [b], or exit [q]:

失败会保留运行目录、日志和已成功阶段；交互模式可重试、改参数、返回或退出。headless/批处理模式不提示，直接返回非零状态并跳过后续阶段。

当前实现对无法识别的菜单输入采用“默认退出”（完成菜单落到 quit，恢复菜单落到 exit），不会重新提示。这是一个已知的交互优化点。

07纯终端 / 无显示器流程

终端-only 时不打开任何窗口，起终点和四角都通过文字输入；路径预览用 yes 确认。

方式 A：显式坐标，适合脚本

$ python main.py map_pipeline/data/input/01_scattered.png \
    --headless --start 2,2 --goal 37,37 --no-drive

方式 B：终端输入起终点

$ python main.py map_pipeline/data/input/图1.jpg \
    --headless --select-terminal \
    --rectify --arena-width-m 2.0 --grid-size-m 0.05
（先输入四个角点）
栅格地图: 40 行 x 47 列，栅格边长 0.05 m
无标记预览: runs/.../result_preview.png
请输入栅格坐标 row,col（地图上方为北；直接回车取消）
起点 row,col: 5,5
终点 row,col: 25,25

方式 C：自动检测

有交互终端但检测不到图形显示时，主入口会自动切到终端选点；stdin/stdout 不是终端时必须显式给 --start/--goal，否则直接报错，不会挂起等待。

参数作用
--headless不打开图形窗口
--select-terminal在终端输入 row,col 起终点
--rectify先做四角透视矫正和裁剪
--corners直接给四个原图像素角点
--arena-width-m / --grid-size-m物理尺度与栅格边长
--accept-path / --yes跳过路径确认 / 驱动确认（自动化用）
