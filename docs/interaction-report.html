00一次普通模式的交互流程

从选图到完成菜单形成可重复使用的会话；本地无驱动与真机驱动共享前三个能力模块。

可选前置步骤：如果输入是俯拍照片而不是干净的正视地图，会在选点之前插入 --rectify 四角矫正与裁剪。它发生在“选图”和“起终点”之间。

07纯终端 / 无显示器流程

纯终端可输入起终点和四角。显式 --headless 默认只保存预览，不驱动；如需驱动，必须传入 --drive --accept-path --yes。不加 --headless 且检测不到图形显示的交互终端，可逐步输入 yes 确认路径和驱动。

方式 A：显式坐标，适合脚本

$ python main.py map_pipeline/data/input/room-16room_000.png \
    --headless --start 313,424 --goal 311,427 --no-drive

方式 B：终端输入起终点

$ python main.py photos/site.jpg \
    --headless --select-terminal \
    --rectify --arena-width-m 2.0 --grid-size-m 0.05
（先输入四个角点）
栅格地图: 行数取决于矫正后长宽比，40 列，栅格边长 0.05 m
无标记预览: runs/.../result_preview.png
请输入栅格坐标 row,col（地图上方为北；直接回车取消）
起点 row,col: 5,5
终点 row,col: 25,25

方式 C：自动检测

有交互终端但检测不到图形显示时，主入口会自动切到终端选点；stdin/stdout 不是终端时必须显式给 --start/--goal，否则直接报错，不会挂起等待。

参数作用
--headless不打开图形窗口
--select-terminal在终端输入 row,col 起终点
--rectify先做四角透视矫正和裁剪
--corners直接给四个原图像素角点
--arena-width-m / --grid-size-m物理尺度与栅格边长
--accept-path / --yes跳过路径确认 / 驱动确认（自动化用）
Windows 文件保存与取消：运行记录和模块结果使用独立临时文件后原子替换；遇到短暂 PermissionError 时最多等待 1.25 秒重试。持续失败时保留原 JSON 和待保存文件并报告实际保存路径，不把错误归咎于地图输入。此机制不支持多个进程并发修改同一批次。在启动选图时 Ctrl+C 简短退出（130），尚未运行运动模块；运动中仍沿用先停车再退出。重新选择当前默认算法会保留临时参数。
